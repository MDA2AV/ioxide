Files over the ring

ioxide.file serves static assets the way the I/O model wants: every file opened once into an immutable snapshot, every read a positional io_uring read - no thread pool, nothing cached in memory, and no HTTP of its own.

Serving files. How the snapshot, the zero-allocation lookup, and lease-safe atomic reloads work is in ioxide.file internals.

Asset snapshots

AssetCache opens every file under a root once (symlinks, hidden and system entries are skipped: on Linux any name starting with a dot, so a .well-known/ directory is not served), keyed by URL path, and keeps just its descriptor, its path and its length at snapshot time - no file bytes, and no HTTP: the status line, Content-Type and Content-Length are the handler's to write. Finding a file is a dictionary lookup (span-based, straight from the request bytes, no allocation); its body is read off the ring on every request.

// One snapshot, shared across all reactors.
var assets = new StaticAssets("/srv/www");

reactor.OnStart = r =>
{
    r.AddService(assets);

    // Per-reactor read concurrency for the ring reads.
    AssetReader.CreatePool(r, readers: 4, bufferBytes: 1 << 20);
};

Serving

var assets  = reactor.GetService<StaticAssets>();
var readers = reactor.GetService<RingPool<AssetReader>>();

if (assets.TryGet(pathBytes, out var asset))
{
    if (asset.Response != 0)
    {
        // Hot path: the baked response - no file I/O, no header formatting.
        await SendChunked(conn, asset.Response, asset.ResponseLength);
    }
    else
    {
        // Large file: positional read off the ring through a rented reader.
        var reader = await readers.RentAsync();

        try
        {
            int read = await reader.ReadAsync(asset.Fd, offset: 0);

            WriteHeader(conn, asset, read);
            await SendChunked(conn, reader.Buffer, read);
        }
        finally
        {
            readers.Return(reader);
        }
    }
}

The reader pool is what keeps concurrent requests from serializing: each rented AssetReader owns its buffer and in-flight slot, and the cache's descriptors are shared and positional, so any number of readers - within a reactor and across reactors - can read the same file at once.

Atomic reloads

Snapshots are immutable; deploys swap them whole. StaticAssets.Reload() builds a fresh AssetCache, swaps it in atomically, and drops its reference to the old one, whose descriptors close when the last lease on it is disposed - a request always sees one whole snapshot, and a read in flight never meets a closed descriptor. If the rebuild fails, the current snapshot stays. Wire it to SIGHUP and a deploy is kill -HUP $(pidof server):

PosixSignalRegistration.Create(PosixSignal.SIGHUP, ctx =>
{
    ctx.Cancel = true;   // handled - don't let the default action terminate us
    assets.Reload();
});
Nothing is cached, so every request reads its file off the ring, from the page cache once the file is warm. A rented AssetReader costs one copy, from its buffer into the write slab; on a cleartext connection or under kTLS TX, TcpConnection.ReadFileAsync reads straight into the slab and costs none.
